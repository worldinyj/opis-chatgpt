# 멀티미디어 교육 콘텐츠 종합 제작계획 V1.1

## 1. 목적과 설계 결정 (2026-11-24)
사건 하나에서 보고서, 사건 이해 영상, 안전문화 교육영상, 핵심 메시지 숏폼, 집합교육 PPT, 토론·실천자료 및 RAG용 지식 데이터를 생성하는 체계. 분석 정확성을 유지하면서 학습 전달은 간결하게 한다. 사용자 결정: 9:16/16:9 가변, 개별 생성과 Gemini Tasks 일괄 작업 병행, 생성 영상뿐 아니라 정지 이미지 슬로우 줌인/줌아웃 및 통제형 편집 허용, 교육 본문은 10원칙 중심, 해당 미진 원칙의 핵심 속성을 별도 한 페이지에 통합 제시. 40속성 원본 분석 방법은 유지한다.

## 2. 콘텐츠 유형과 기준
| 유형 | 목적 | 기본값(가변) | 근거 |
|---|---|---|---|
| REPORT | 상세 안전문화 분석 | A4 5쪽 이상 목표 | KINS 원본 |
| INCIDENT_UNDERSTANDING | 사건 전반 이해 | 120~150초 | KINS 원본 |
| SAFETY_CULTURE_LEARNING | 원칙 중심 교육 | 약 120초 | KINS + report.md |
| KEY_MESSAGE_SHORT | 한 원칙 또는 학습행동 | 30초 | 학습 원장 |
| CLASSROOM_PPT | 집합교육/토론 | 16:9, 10~14장 제안 | 원본+보고서+학습 원장 |
| DISCUSSION_ACTION | 질문/토론/실천 | MD 및 PPT 노트 | 보고서 4·5장 |
| KNOWLEDGE_DATA | 검색/RAG | 구조화 근거 및 버전 | 승인된 분석 |

기본 길이는 고정 제한이 아니다. 원본 패키지 템플릿 자체는 150초 목표(인트로 8초/아웃트로 10초)이며, 앞서 제안한 120초/20구간은 OPIS의 교육용 선택 프로필이다.

## 3. 공통 모델
사건 ID → 원본 판본 및 분석 버전 → 사실 원장 F*와 학습 원장 L* → 유형별 제작 manifest → 스토리보드/대본/프롬프트/슬라이드 계획 → 자산 생성/통제형 편집 → 검토/승인/배포. 원본과 분석보고서의 변경 시 파생물 stale 표시, 근거와 자산 의존 관계를 재검토한다.

## 4. 제작 경로
- 개별: 실제 참조 이미지를 첨부한 이미지 생성(Codex 등) → 필요한 구간 Grok I2V → 자산 검수.
- 배치: Gemini Tasks 사용자가 실행하는 작업 단위에 동일한 brief/manifest/참조/개별 프롬프트를 제공하고, 결과 파일과 설정을 매핑·수입한다. 현재 서비스의 지원 포맷·실행 가능 여부는 실제 사용 시 확인한다. 자동 연결/API 구현이나 작업 실행을 의미하지 않는다.
- 정지 이미지 편집: 승인 이미지에 느린 줌인/줌아웃 또는 팬, 컷, 자막. 실제 사건 동작으로 오해되지 않게 하고 이미지 자체를 변형하지 않는다.
- 통제형 편집: 제목/원칙·속성 요약/정확한 수치/교육 질문/그래픽/아웃트로를 편집에서 제작. 필요하면 생성 이미지를 배경으로 혼합.
- 동일한 영상에서도 구간별 제작 경로를 자유롭게 혼용. 제작 방식은 학습목적·가독성·비용·일관성으로 결정; 생성 영상 비율 하한 없음.

## 5. 가변 출력 프로필
프로젝트별 또는 산출물별 aspect_ratio = 9:16 또는 16:9. 480p/720p/1080p 등 실제 지원 해상도 확인 후 width/height/fps 기록. 9:16은 모바일, 16:9는 집합교육 및 모니터 권장. 화면비별 프레이밍·자막 안전영역·요약 카드 재배치·검수 필요. 무조건 중앙 크롭하지 않는다. 양쪽 비율은 선택사항이며 각 버전의 미디어 승인 별도. 6초를 기본 생성 클립으로 사용하되 정지/통제형 구간과 음성에 따라 가변. 실제 길이 = 구간 합 - 겹침 전환; 내부 페이드 중복 차감 금지.

## 6. 교육 원칙 표시 정책
보고서와 데이터는 40개 속성을 모두 검토하되 영상/슬라이드 본문은 근거 있는 10원칙 코드·명칭·현장 행동 중심. 단순 코드 개수로 원칙 취약 정도나 우선순위를 확정하지 않는다. 한 개 속성 후보라도 연관 원칙으로 묶을 수 있으나 전체 원칙 미진의 확정 평가가 아님을 표시한다. 속성 종합 화면 한 장(영상 카드/PPT 슬라이드)에서 선정 원칙별 모든 핵심 후보 속성 코드와 명칭을 함께 표시. 추가 검토 후보 제외, 선정 개수 제한 없음. 실제 화면에서 읽을 수 있는 글자 크기/정지 시간 확인. 세로 화면에서는 2열 또는 그룹별 압축 레이아웃을 검토하고, 필요하면 카드 시간을 늘리거나 최종 정지 화면/첨부 자료를 제공. 가독성을 희생하지 않는다.

## 7. 저장소 구조
- video/: 영상 공통 제작 지침, 원본 이식 기록, 향후 schemas/scripts/tests/templates.
- education/ppt/: 편집 가능한 집합교육 PPT 제작 규격과 향후 템플릿·검증.
- cases/YYYY/ID/media/: 공통 학습기획과 콘텐츠 카탈로그; 이해영상·교육영상·숏폼·PPT별 하위 경로(기획/manifest/근거/검토/생성 문서). 공통 원본은 사건 source.md, report.md.
- index/media.json: 향후 실제 콘텐츠 카탈로그 자동 생성; 현재는 첫 사건 계획에 명시.
- 대용량 이미지/영상/음원은 GitHub에 기본 저장하지 않으며 로컬/승인 저장소와 해시 참조.

## 8. 상태 및 게이트
PLANNED → SCRIPT_DRAFT → CONTENT_REVIEWED → ASSET_READY → EDITED → FINAL_QC → APPROVED. 독립검토 전에도 기획·대본 작성 가능. 원본 사실과 해석을 교차검토한 후 자산 제작 진행; 최종 전문가 승인 전 배포 확정 금지. 유료 호출 또는 외부 배치는 사용자 명시 요청 필요. 본 문서의 설계는 기능 구현·영상/PPT 생성 완료를 뜻하지 않는다.
